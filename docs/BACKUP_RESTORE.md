# 工作站加密备份与恢复

入口：**运行环境 → 工作站备份与恢复**。备份应用内持久化 Linux 工作站；Android WebView 的网页存储、Cookie 和未发送草稿留在本机，不随 v1 备份跨设备迁移。官方前端源码与页面逻辑没有修改。

## 使用

1. 保存原生文件编辑器内容，停止 OpenCode、终端和 Debian 桌面，等待文件操作结束。
2. 选择“生成加密备份”，输入并再次确认至少 12 个字符的密码。生成完毕后选“保存到文件”，通过系统文件选择器保存 `.ocawork`。
3. 导入时选择备份并输入密码。应用先在私有目录中解密、验证全部加密段与文件记录，当前环境保持不变。
4. 原生确认界面显示时间、条目、数据量和 OpenCode 版本。确认备份来源可信后才恢复；成功后重开工作区。
5. “还原上次恢复前的整套环境”恢复原工作站，较新的工作也会保留。它恢复项目、home、Debian 和会话；独立 OpenCode 更新页面的回退只切换程序与会话。

密码不会进入 Intent、日志或 SavedState；请求只传内存中的一次性标识，`CharArray` 在任务结束/取消时清除。密码遗失无法恢复。备份可能包含 SSH 私钥、模型 API 密钥、Git/gh 配置和 Linux 浏览器资料，应自行保管密码与备份。

## 数据范围

捕获 `rootfs`、`workspace`、`home`、`opencode-state`、`desktop-state`、`opencode-runtimes` 和受限的 `runtime-config`。包含 apt/桌面定制、数据库与 WAL、项目、用户目录、Linux Chromium profile、活动运行包及其发布者证明。原生布局、悬浮球透明度/位置、WebView 调度选择、项目目录和预览端口通过带类型的白名单迁移；不复制 Android 凭据设置。

不嵌套打包 `backups`，不打包 tmp/shm、进程 socket/设备节点、桌面运行目录、网关凭据、后端 `service-dev.json` 或宿主生成的工具/令牌。`runtime-config` 只允许活动 OpenCode UUID 指针及其 AtomicFile 备份；导入也拒绝其他配置，不能注入宿主恢复日志或设备绑定的凭据。宿主数据在正常启动时重新生成。

PRoot 的 `/root`、`/workspace` 等挂载点记录为目录占位，实际持久数据由对应独立根目录捕获；`/dev`、`/proc`、`/sys` 和临时目录由当前宿主重新挂载。占位目录可能为 `000` 权限，导出不改变其权限。无法读取的自定义源目录会使导出失败，不改变源权限或生成可保存的半份备份。

保留 UTF-8 路径（含中文/emoji）、普通 Unix 读写执行位、mtime、符号链接和命名管道。链接目标作为数据处理，不沿外部链接读取文件；外部目录内容不会因一个链接自动加入备份。内核硬链接记录转换为当前 PRoot 的 link2symlink 表示；既有 PRoot 链接在暂存和最终切换时重新定位，保留 `ln/stat`、写入和 unlink 语义。临时目录权限调整只发生在私有暂存/自有清理树，随后恢复，不调整活动源树。

Chromium 兼容模式不会因导入自动启用。备份中存在该选项时，原生确认界面另有默认关闭的选择；开启会关闭其 Linux 进程沙箱。Linux 浏览器 profile 仍保留。

## 加密与边界

外层 `OCABAK01`：随机 16 字节 salt，PBKDF2-HMAC-SHA256 固定 600000 次，AES-256-GCM 包装每份新生成的 Tink keyset。数据使用 Tink Android 1.24.0 `AES256_GCM_HKDF_1MB` Streaming AEAD，完整头参与 AAD。参数固定并在创建解密器前校验，不接受攻击者指定的大段分配或其他 KDF 参数。实现依据 [Tink Streaming AEAD](https://developers.google.com/tink/streaming-aead?hl=en) 与[大文件加密接口](https://developers.google.com/tink/encrypt-large-files-or-data-streams)。这不是自制加密算法，也不依赖源设备 Android Keystore，因此可用密码在同架构、兼容 Host 中恢复。

明文为 gzip 中的 `OCAFS001` 文件记录流。元数据最多 64 KiB、JSON 深度最多 32，路径最多 4096 字节/256 层、最多 200 万条目，数据总量还受真实剩余空间与保留空间限制。逐个记录检查父目录、重复路径、长度和类型；不先构造不受限的 TAR/PAX 对象。尾部计数、gzip 结束及最后一个 AEAD 段全部验证后才能返回可审阅的暂存树。错误密码、截断、篡改、路径穿越和符号链接父目录均不能激活。

包名、ABI、Host versionCode 和原生设置格式必须兼容。已安装环境的活动 OpenCode 或 rootfs 内置程序须通过当前 APK 发布者签名及完整 SHA-256 验证；不能在确认前执行备份内程序。恢复 Linux 镜像仍意味着接受其中的 Linux 软件与配置，所以界面要求用户确认来源。

## 事务与生命周期

维护所有者排除服务、PTY、新终端构造/关闭和原生文件任务；文件任务在启动协程前取得所有者。恢复日志位于不参与切换的 `files/maintenance/workstation-restore.json`。确认后先写持久意图，再逐目录重命名旧树到 `backups/workstation-restore-<uuid>/previous`，放入新树并恢复白名单设置。真实官方 CLI 在随机 loopback 端口验证版本、授权成功和匿名 401，通过后记录提交。

备份服务检查所有活动原生编辑器的未保存内容。维护期间不接受延迟到达的编辑输入；环境世代编号让旧窗口在其他窗口重开后仍无法写入恢复后的文件。CPU wake lock 在 IO 期间有界续期，等待确认/结束时释放，长时间停滞后会超时，不永久唤醒设备。

未提交的恢复回到旧树；已提交的恢复完成提交；已确认的“还原”被中断后继续完成还原。失败的新树保留在 `failed`，还原前的较新树保留在 `after-restore`。连续恢复可逐次还原。原生服务启动前先恢复日志，恢复中不会补建暂时缺失的根目录，DNS 回调也受所有者约束。成功切换后必须重开工作区，旧编辑器不能继续覆盖恢复后的文件。

加密文件先保存在应用私有备份目录，完整成功后才提供系统保存入口。保存失败/取消只处理本次创建的目标文件，私有加密原件保留。导入明文只存在于应用私有暂存目录。已有环境和旧备份不递归删除；目前只提供加密导出暂存副本的删除，旧环境历史和中断暂存的管理界面仍待完成，会占用额外空间。
