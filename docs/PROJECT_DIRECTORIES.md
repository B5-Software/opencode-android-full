# 项目目录衔接

官方 dev 服务模式会将守护进程的工作目录改到 HOME。Agent、文件工具和会话按各自的 `location.directory` 工作，不能把守护进程的 `/root` 当成项目目录。Android Host 保留官方这一行为，通过现有 location/session API 衔接原生入口。

运行环境启动时尝试注册 `/workspace` 默认项目。注册失败不会终止已经就绪的后端，用户可从文件页重试。

文件页及文件夹操作菜单增加“在此开始 OpenCode 会话”和“在此打开终端”。前者通过官方 session API 明确传递目录，再打开官方的 `/server/<serverKey>/session/<id>` 页面；不会改写聊天界面或向页面注入 Android 系统桥。未保存的原生编辑器内容需要先保存，才能从该页开始会话。

`WorkspaceContext` 记录最近选择的本地项目目录，并保存到应用私有设置。官方页面发生会话导航时，Host 只识别固定本地 origin 和规范的本地 server key，再以原生凭据读取会话元数据。目录取自已认证的官方 API，不从不可信网页文字中推断。迟到的查询不能覆盖更新的原生目录选择。

新终端使用所选目录创建真实 PTY；已有终端不自动执行 `cd`。全局终端选择状态保证从文件夹打开的新终端获得焦点。目录作为独立 argv 传递，不拼接用户路径为 shell 代码。终端及桌面入口使用物理目录语义处理符号链接和 `..`。

原生文件面板当前管理 `/workspace`。切换到该树中的项目时会跟随；若编辑器有未保存内容，先保留编辑器并要求确认。Linux 项目在该树之外时，新终端和桌面仍可使用其绝对目录，其他目录的文件可通过官方工具或桌面访问；原生文件面板不会因此扩大其现有文件访问范围。

桌面启动后默认打开当前项目的 Thunar 窗口。桌面控制栏“项目文件夹”可在不重启 X server 的情况下打开最新项目。通过私有 D-Bus 会话地址复用已有 Thunar，不设置全局浏览器桥；宿主入口仅响应可信桌面页面的真实用户点击。目录同样是独立参数，D-Bus 地址文件权限为 0600，停止时删除。额外文件夹进程数量有界，随桌面停止清理。
